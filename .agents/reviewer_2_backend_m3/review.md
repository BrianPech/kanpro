## Findings & Security Evaluations

### 1. Server-Only Service Role Client Isolation (`src/lib/supabase/admin.ts`)
- **Assessment**: **PASSED (No Issues)**
- **Observation**:
  - `import "server-only";` is placed at line 1.
  - Environment variables `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are validated with descriptive error handling that does not leak secret values.
  - Session persistence and auto-refresh are disabled (`persistSession: false`, `autoRefreshToken: false`, `detectSessionInUrl: false`), ensuring that admin operations do not mutate cookie headers or interfere with current user sessions.
  - Client component scan (`grep_search`) confirmed zero imports of `admin.ts` or `SUPABASE_SERVICE_ROLE_KEY` in frontend bundles.

### 2. Identity Management & Staff Actions (`src/app/(dashboard)/dashboard/admin/staff/actions.ts`)
- **Assessment**: **PASSED (No Issues)**
- **Observation**:
  - `requireAdminAuth()` strictly validates session authenticity (`supabase.auth.getUser()`) and queries `profiles.role === 'admin'` from the database, eliminating metadata spoofing.
  - `createAdminStaffMember()` eliminated `supabase.auth.signUp()` and `crypto.randomUUID()` in favor of real `auth.users.id` generated by `supabaseAdmin.auth.admin.createUser()`.
  - **Candidate / Company Collision Guard**: Queries `profiles` by sanitized email. If a user exists with role `'candidate'` or `'company'`, the action immediately rejects with a safe, descriptive error message without mutating the user's role or auth state.
  - **Existing Admin Idempotency**: If the user is already an admin, it updates their profile and `admin_staff_members` metadata without recreating auth credentials.
  - **Compensatory Rollback**: If a newly created user encounters a failure during profile promotion (`profiles.upsert`) or staff assignment (`admin_staff_members.upsert`), `supabaseAdmin.auth.admin.deleteUser(targetProfileId)` is executed inside a catch block to eliminate orphaned auth identities. Rollback does not apply to pre-existing users.
  - **Self-Deletion Guard**: `deleteAdminStaffMember()` explicitly prevents an admin from deleting or downgrading their own account.

### 3. Public Auth Callback Hardening (`src/app/(auth)/auth/callback/route.ts`)
- **Assessment**: **PASSED (No Issues)**
- **Observation**:
  - Public callback role resolution is restricted strictly to `"candidate" | "company"`.
  - Attempts to inject `?role=admin` or `user_metadata.role = 'admin'` are safely ignored and defaulted to `'candidate'`.
  - Redirect URLs (`redirectToParam`) are validated to ensure only safe relative paths or same-origin URLs are allowed, mitigating open redirect vulnerabilities.

### 4. Authoritative Session Resolution (`src/modules/auth/services/dashboard-session.ts` & `require-admin.ts`)
- **Assessment**: **PASSED (No Issues)**
- **Observation**:
  - `getDashboardSession()` and `requireAdmin()` query `profiles.role` in PostgreSQL as the single source of truth.
  - Unauthenticated users and non-admin users attempting to access admin routes are redirected appropriately.
